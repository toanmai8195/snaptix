## pnpm workspace: script gốc chạy đệ quy
- **Chủ đề**: `node/pnpm`
- **Bối cảnh**: một lệnh ở gốc phải build/test mọi package, kể cả khi chưa có package nào.
- **Cách làm & lý do**: `pnpm-workspace.yaml` khai báo `apps/*`, `packages/*`. Script gốc dùng `pnpm --recursive --if-present <script>`: `--if-present` bỏ qua package không có script đó thay vì fail. `dev` chỉ chạy `./apps/*` và `--parallel` để các dev server chạy đồng thời (không chờ nhau kết thúc).
- **Bẫy / lưu ý**: thư mục chỉ có `.gitkeep` (không có `package.json`) không phải package — pnpm bỏ qua, nên khung thư mục từ P0-T01 không gây lỗi.
- **Code**: [package.json#L9-L15 — scripts](../../../../app/package.json#L9-L15)

## Pin phiên bản pnpm và Node
- **Chủ đề**: `node/pnpm`
- **Bối cảnh**: CI và máy dev phải dùng cùng phiên bản pnpm để lockfile không bị ghi đè khác định dạng.
- **Cách làm & lý do**: `"packageManager": "pnpm@11.18.0"` (Corepack đọc trường này) và `"engines": {"node": ">=22"}`. Pin đúng bản đang cài trên máy thay vì bản mới nhất để không buộc tải thêm.
- **Code**: [package.json#L5-L8 — packageManager, engines](../../../../app/package.json#L5-L8)

## `--filter "...[ref]"` chỉ thấy thay đổi đã track
- **Chủ đề**: `node/pnpm`, `git`
- **Bối cảnh**: CI (P0-T04) sẽ dùng `pnpm --filter "...[origin/main]"` để chỉ build/test package bị ảnh hưởng.
- **Cách làm & lý do**: `[ref]` = package có file thay đổi so với `ref`; tiền tố `...` kéo thêm package **phụ thuộc** vào chúng. Test bằng repo git tạm: commit hai package, sửa một file đã track → chỉ package đó chạy.
- **Bẫy / lưu ý**: pnpm dùng `git diff` nên **file mới chưa track không được tính** — lần đầu test fail với "No projects matched". Trong CI mọi thay đổi đã commit nên không ảnh hưởng; khi thử local nhớ `git add`.
- **Code**: [scripts/test/pnpm-workspace.test.sh#L54-L65 — TC04](../../../../../../scripts/test/pnpm-workspace.test.sh#L54-L65)
