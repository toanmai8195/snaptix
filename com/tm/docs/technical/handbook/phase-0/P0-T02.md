## Healthcheck + `up --wait` thay cho sleep
- **Chủ đề**: `docker/compose`
- **Bối cảnh**: script và test cần biết khi nào PG/Mongo/Redis thực sự nhận kết nối.
- **Cách làm & lý do**: mỗi service có `healthcheck` dùng công cụ sẵn trong image (`pg_isready`, `mongosh --eval ping`, `redis-cli ping`, `wget /-/ready`). `docker compose up -d --wait --wait-timeout 120` chỉ trả về khi mọi service healthy (hoặc running nếu không có healthcheck) — không cần `sleep` đoán mò.
- **Bẫy / lưu ý**: image tối giản (Tempo, otel-collector-contrib) không có shell/wget → không viết healthcheck được; kiểm tra từ host qua HTTP (`/ready`, extension `health_check` cổng 13133). Trong `test` của healthcheck, biến môi trường container phải viết `$${VAR}` để compose không nội suy lúc parse.
- **Code**: [docker-compose.yml#L14-L31 — pg healthcheck dùng chung](../../../../../../deploy/docker-compose.yml#L14-L31)

## Luồng observability: OTLP → collector → Tempo / Prometheus → Grafana
- **Chủ đề**: `observability`, `otel`
- **Bối cảnh**: app chỉ nên biết một endpoint (OTLP), backend có thể đổi.
- **Cách làm & lý do**: collector nhận OTLP gRPC 4317 / HTTP 4318; pipeline trace → `otlp/tempo`, metric → exporter `prometheus` (cổng 8889, Prometheus scrape). `resource_to_telemetry_conversion` đưa `service.name` thành label metric. Grafana provision sẵn datasource Prometheus + Tempo (Tempo link service map sang Prometheus).
- **Bẫy / lưu ý**: kiểm tra đầu-cuối bằng cách tự gửi một span OTLP JSON (trace ID ngẫu nhiên `openssl rand -hex 16`) rồi truy vấn `GET /api/traces/<id>` của Tempo — có độ trễ ingest vài giây nên phải retry.
- **Code**: [otel-collector.yaml](../../../../../../deploy/observability/otel-collector.yaml), [compose.test.sh#L79-L85 — gửi span thử](../../../../../../scripts/test/compose.test.sh#L79-L85)

## Test compose không phá dữ liệu dev
- **Chủ đề**: `docker/compose`, `testing`
- **Bối cảnh**: test có bước `down -v` (xoá volume).
- **Cách làm & lý do**: chạy với `-p snaptix-test` → container và volume mang tiền tố riêng, dữ liệu project `snaptix` của dev không bị đụng. `trap ... down -v` luôn dọn dẹp. Script kiểm tra cổng bận bằng `lsof` và dừng sớm với hướng dẫn thay vì fail khó hiểu.
- **Code**: [compose.test.sh#L12 — project riêng](../../../../../../scripts/test/compose.test.sh#L12), [compose.test.sh#L28-L33 — kiểm tra cổng + trap](../../../../../../scripts/test/compose.test.sh#L28-L33)
