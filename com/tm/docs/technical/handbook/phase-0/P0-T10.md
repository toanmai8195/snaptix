## CI mỏng: workflow chỉ gọi script
- **Chủ đề**: `ci/github-actions`, `bash`
- **Bối cảnh**: lỗi CI mà không tái hiện được ở local thì sửa rất chậm (push → chờ → đọc log).
- **Cách làm & lý do**: toàn bộ bước nằm trong `scripts/ci/run.sh server [BASE]`: gazelle `-mode=diff` → golangci-lint → `bazel build //...` → `bazel test` target bị ảnh hưởng. Workflow chỉ chuẩn bị môi trường (checkout, Go, Bazel + cache) rồi gọi script; `make test` gọi cùng script → local và CI chạy y hệt. Trên GitHub, `step()` in `::group::` (log thu gọn theo bước) và `fail()` in `::error::` (annotation đỏ trên trang run).
- **Bẫy / lưu ý**: gazelle `-mode=diff` in diff ra stdout — script kiểm output rỗng thay vì dựa vào exit code. `set -euo pipefail` để lỗi ở bất kỳ lệnh nào dừng script.
- **Code**: [scripts/ci/run.sh — server](../../../../../../scripts/ci/run.sh), [.github/workflows/ci.yml](../../../../../../.github/workflows/ci.yml)

## golangci-lint pin phiên bản, chạy bằng go run
- **Chủ đề**: `go/lint`
- **Bối cảnh**: cần lint giống nhau ở mọi máy, không bắt cài tay.
- **Cách làm & lý do**: `go run github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.6.2 run ./...` (v2.6.2 cần Go 1.24.0 — chạy được với Go 1.24.1 của dự án); cấu hình v2 tối thiểu `linters.default: standard` (errcheck, govet, ineffassign, staticcheck, unused) + formatter `gofmt`. Pin phiên bản vì bản mới thường thêm rule → CI đỏ mà code không đổi. Lần đầu chạy bắt 6 lỗi errcheck, tất cả là `Close()` bỏ qua lỗi (`defer resp.Body.Close()`...) → sửa thành `defer func() { _ = x.Close() }()` — bỏ lỗi **tường minh**.
- **Bẫy / lưu ý**: `go vet` không bắt lỗi bị bỏ qua; errcheck mới bắt. `defer x.Close()` nhìn vô hại nhưng errcheck vẫn báo.
- **Code**: [com/tm/server/.golangci.yml](../../../../server/.golangci.yml)

## Test target bị ảnh hưởng bằng bazel query rdeps
- **Chủ đề**: `bazel/query`, `git`
- **Bối cảnh**: monorepo lớn dần; chạy hết test mỗi PR tốn thời gian — G14 yêu cầu "CI chỉ test target bị ảnh hưởng".
- **Cách làm & lý do**: `git diff --name-only BASE...HEAD -- com/tm/server` (ba chấm = so với điểm rẽ nhánh, không tính commit mới trên base) → mỗi file thành label: tìm thư mục gần nhất có `BUILD.bazel` (package), label `//pkg:file.go` (source file cũng là target) → `bazel query 'kind(".*_test rule", rdeps(//..., set(...)))'`. `rdeps(U, X)` = mọi target trong U phụ thuộc (bắc cầu) vào X. File BUILD bị sửa hoặc file bị xoá → `//pkg:all`. Đổi `MODULE.bazel`, `go.mod`, `.bazelrc`, `*.bzl`, `tools/` → test hết (ảnh hưởng toàn cục). BASE rỗng / toàn số 0 (push đầu của nhánh mới) / không tồn tại → test hết. Kiểm bằng `git worktree` tạm với commit giả lập: sửa `httpx/health.go` → `httpx_test`, `server_test`, `integration_test` (không có `migrations_test`); sửa migration → `migrations_test`, `integration_test`; sửa docs → không test nào.
- **Bẫy / lưu ý**: CI cần `fetch-depth: 0` (checkout mặc định chỉ 1 commit → không có BASE để diff). `--keep_going` để file không thuộc target nào không làm hỏng cả truy vấn.
- **Code**: [scripts/ci/bazel-affected-tests.sh](../../../../../../scripts/ci/bazel-affected-tests.sh)

## Workflow: lọc đường dẫn ở job, cache Bazel
- **Chủ đề**: `ci/github-actions`, `bazel`
- **Bối cảnh**: PR chỉ sửa docs không nên chạy job Go (P0-AT05); job Go cần Bazel cache để không build lại từ đầu.
- **Cách làm & lý do**: job `changes` dùng `dorny/paths-filter` xuất `server=true/false` (`com/tm/server/**`, `.github/**`, `scripts/ci/**`); job `server` có `needs: changes` + `if:`. Lọc ở job thay vì `on.paths`: một workflow nhiều job, job không liên quan hiện **skipped** (vẫn có trạng thái cho required check). `setup-go` theo `go.mod` (cho golangci-lint), `bazel-contrib/setup-bazel` cache Bazelisk + disk cache + repository cache. BASE = `pull_request.base.sha` hoặc `github.event.before`. `permissions: contents: read`; `concurrency` huỷ lần chạy cũ khi push mới.
- **Bẫy / lưu ý**: workflow chạy cho `push` mọi nhánh để kiểm được CI bằng nhánh thử khi chưa có `gh`. Với push lên nhánh **khác `main`**, `dorny/paths-filter` mặc định so với `main` chứ không so với commit trước → nhánh chỉ sửa docs vẫn bị coi là đổi server (gặp thật ở AT05, lịch sử lệch do squash-merge) → đặt `base: github.event.before` cho push (trừ nhánh mới, `before` toàn số 0). GitHub **không chạy** workflow `pull_request` khi PR đang conflict. Log job cần đăng nhập mới tải được (API 403) → để chứng minh integration test không bị skip trên CI, `run.sh` truyền `--test_env=PGTEST_REQUIRE_DOCKER=1` và `pgtest.Run` thoát lỗi khi thiếu Docker: CI xanh ⇒ test đã chạy thật. Annotation (`::error::`) thì đọc được qua API check-runs không cần đăng nhập.
