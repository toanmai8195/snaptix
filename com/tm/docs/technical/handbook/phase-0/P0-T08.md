## go:embed cho migration
- **Chủ đề**: `go/embed`, `bazel`
- **Bối cảnh**: test cần đọc `db/core/migrations/*.sql`; `go test` chạy ở thư mục package, `bazel test` chạy trong sandbox/runfiles → đường dẫn tương đối khác nhau.
- **Cách làm & lý do**: package `db/core/migrations` với `//go:embed *.sql` + `var FS embed.FS` — compiler đóng gói file vào binary, cả `go` và Bazel thấy cùng dữ liệu. File Go phải nằm **cạnh** file `.sql` vì `go:embed` không lấy được thư mục cha. Gazelle đọc chỉ thị và sinh `embedsrcs`; thêm migration mới phải chạy gazelle. Unit test kiểm quy ước tên `NNNNN_ten.sql`, đánh số liên tục, có `-- +goose Up/Down`.
- **Bẫy / lưu ý**: `//go:embed` phải sát trên khai báo biến, không có dấu cách sau `//`. `scripts/migrate.sh` (goose CLI) vẫn chạy bình thường khi thư mục có thêm file `.go`.
- **Code**: [db/core/migrations/migrations.go — FS](../../../../server/db/core/migrations/migrations.go), [migrations_test.go — TestFSContainsSequentialMigrations](../../../../server/db/core/migrations/migrations_test.go)

## testcontainers-go: wait strategy, cổng ngẫu nhiên, dọn container
- **Chủ đề**: `go/testing`, `docker/testcontainers`
- **Bối cảnh**: integration test cần PG thật, sạch mỗi lần chạy, không phụ thuộc compose.
- **Cách làm & lý do**: module `postgres` (`postgres.Run`) với image cùng compose (`postgres:17.6-alpine`). `BasicWaitStrategies`: chờ log "ready to accept connections" **2 lần** (image PG khởi động tạm để chạy init rồi restart) + chờ cổng map ra host (Docker Desktop macOS cần proxy) → hết lỗi "connection refused" ngẫu nhiên. Cổng 5432 map ra cổng host ngẫu nhiên → không đụng compose; `ConnectionString` trả đúng cổng. Dọn: `Terminate` qua cleanup; process bị `kill -9` thì **Ryuk** (container đi kèm) thấy kết nối đứt và xoá mọi container cùng session sau ~10–15s (đo được ở TC04).
- **Bẫy / lưu ý**: đăng ký dọn **trước** khi kiểm `err` của `Run` (lỗi ở bước chờ vẫn đã tạo container). Không giả lập được "không có Docker" bằng `DOCKER_HOST` sai — testcontainers dò 6 nguồn (`tc.host`, `DOCKER_HOST`, docker context, `/var/run/docker.sock`...) và bỏ qua nguồn hỏng; phải tắt Docker Desktop thật. `go mod tidy` cần pin `grpc-gateway/v2 v2.16.0` (indirect): test của một dependency otel import nó, tidy tự tìm bản mới nhất (đòi Go 1.26). testcontainers-go pin v0.40.0 (v0.41+ đòi Go 1.25).
- **Tham khảo**: [testcontainers-go postgres module](https://golang.testcontainers.org/modules/postgres/)

## Một container cho cả package, database template cho từng test
- **Chủ đề**: `go/testing`, `pg/template-database`, `pg/migration`
- **Bối cảnh**: bật container mỗi test tốn vài giây; dùng chung một DB thì test giẫm dữ liệu nhau.
- **Cách làm & lý do**: `TestMain(m)` gọi `pgtest.Run(m)`: `flag.Parse()` (để đọc `-short`), kiểm Docker, khởi động **một** container, chạy goose như thư viện (`goose.NewProvider(DialectPostgres, *sql.DB, migrations.FS)` với driver `pgx/v5/stdlib`) vào `core_template`, `m.Run()`, rồi xoá container. `pgtest.NewDB(t)`: `CREATE DATABASE test_N TEMPLATE core_template` (PG copy file của DB có sẵn schema — vài chục ms, không chạy lại migration), mở pool, cleanup đóng pool + `DROP DATABASE ... WITH (FORCE)`. Tên DB đánh số bằng `atomic.Int64` vì test song song; tên là identifier nên dùng `pgx.Identifier{}.Sanitize()` thay cho tham số `$1`. Helper ở `internal/pgtest` (quy tắc 3 tầng: mới core dùng).
- **Bẫy / lưu ý**: PG **không cho** dùng DB làm template khi còn kết nối vào nó → đóng `*sql.DB` của goose ngay sau migration; không test nào kết nối vào template. `-short` / không Docker → `NewDB` skip với lý do rõ ràng thay vì fail.
- **Code**: [pgtest/pgtest.go#L59-L116 — Start, init, migrate](../../../../server/services/core/internal/pgtest/pgtest.go#L59-L116), [pgtest.go#L119-L152 — Container.NewDB](../../../../server/services/core/internal/pgtest/pgtest.go#L119-L152), [pgtest.go#L203-L242 — Run, NewDB, RequireDocker](../../../../server/services/core/internal/pgtest/pgtest.go#L203-L242), [integration/isolation_test.go — TestEachTestGetsOwnDatabase](../../../../server/services/core/integration/isolation_test.go)

## Test phá hạ tầng: container riêng, cổng host cố định
- **Chủ đề**: `go/testing`, `docker/testcontainers`, `pg/pgx`
- **Bối cảnh**: P0-AT03 cần dừng PG rồi bật lại; dừng container dùng chung sẽ làm hỏng test khác.
- **Cách làm & lý do**: test tự `pgtest.Start` container riêng. Docker cấp cổng host ngẫu nhiên **mỗi lần start** → sau `Stop`/`Start`, DSN của pool trỏ sai cổng. `pgtest.FixedHostPort()` hỏi OS một cổng trống (`net.Listen(":0")` rồi đóng) và bind cố định qua `WithHostConfigModifier` → pool cũ tự kết nối lại, đúng như core thật khi PG restart. Kiểm bằng `httptest.NewServer` (HTTP thật qua TCP) và `eventually` (poll tới khi đạt trạng thái hoặc hết giờ) vì hạ tầng thật cần thời gian đổi trạng thái.
- **Bẫy / lưu ý**: sau khi PG restart, kết nối cũ trong pool `admin` đã chết → lần `DROP DATABASE` đầu lỗi `57P01 terminating connection` → cleanup thử lại vài lần (pool bỏ kết nối chết, mở kết nối mới).
- **Code**: [pgtest.go#L157-L171 — FixedHostPort](../../../../server/services/core/internal/pgtest/pgtest.go#L157-L171), [integration/readyz_test.go#L60 — TestReadyzWhenPostgresStops](../../../../server/services/core/integration/readyz_test.go#L60)

## Tag Bazel cho test cần Docker
- **Chủ đề**: `bazel`, `go/testing`
- **Bối cảnh**: integration test cần Docker, không phải máy / CI job nào cũng có.
- **Cách làm & lý do**: integration test ở package riêng `services/core/integration` → `go_test` riêng; thêm tay `size = "large"` (timeout 900s) và `tags = ["requires-docker", "requires-network"]` — gazelle giữ nguyên. Lọc: `bazel test --test_tag_filters=-requires-docker //...`. Trên macOS, darwin-sandbox vẫn cho test đọc socket Docker Desktop — không cần `no-sandbox` hay `--test_env=DOCKER_HOST` (CI Linux kiểm lại ở P0-T10).
- **Bẫy / lưu ý**: Bazel không in `-v` → test bị skip vẫn báo `PASSED`; kiểm bằng `--test_arg=-test.v --test_output=all`.
- **Code**: [services/core/integration/BUILD.bazel](../../../../server/services/core/integration/BUILD.bazel)
