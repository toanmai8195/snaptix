## RED và hợp đồng metric OpenTelemetry
- **Chủ đề**: `observability`, `otel`, `prometheus`
- **Bối cảnh**: dashboard phải làm trước khi có service, nên cần một "hợp đồng" tên metric mà service sau này tuân theo.
- **Cách làm & lý do**: dùng metric chuẩn semconv `http.server.request.duration` (histogram, đơn vị giây) mà `otelhttp` (Go) / instrumentation HTTP của Node tự phát. Collector (exporter `prometheus`) đổi tên: dấu chấm → gạch dưới, thêm hậu tố đơn vị → `http_server_request_duration_seconds_bucket|_count|_sum`; thuộc tính → label (`http_response_status_code`, `http_route`); `resource_to_telemetry_conversion` đưa `service.name` → `service_name`. RED: **R**ate = `rate(_count)`, **E**rrors = tỉ lệ `_count` có status `5..`, **D**uration = `histogram_quantile` trên `_bucket`.
- **Bẫy / lưu ý**: chia tỉ lệ lỗi phải `clamp_min(mẫu, 1e-9)` để không ra `NaN` khi không có traffic. `histogram_quantile` cần `sum by (le, ...)` — thiếu `le` là kết quả sai.
- **Code**: [red.json — panel + biến service](../../../../../../deploy/observability/grafana/provisioning/dashboards/json/red.json)

## Provision dashboard bằng file, không tạo tay trên UI
- **Chủ đề**: `observability`, `grafana`
- **Bối cảnh**: dashboard tạo trên UI sẽ mất khi `make nuke`, không review được qua git.
- **Cách làm & lý do**: provider `type: file` trỏ tới thư mục JSON (`allowUiUpdates: false`, `disableDeletion: true`); Grafana nạp lúc khởi động → API trả `provisioned: true`. Biến `service` = `label_values(..._count, service_name)`, `includeAll` với `allValue: ".+"` để truy vấn regex `service_name=~"$service"`.
- **Code**: [dashboards.yaml](../../../../../../deploy/observability/grafana/provisioning/dashboards/dashboards.yaml)

## Test dashboard bằng metric OTLP giả lập
- **Chủ đề**: `otel`, `testing`
- **Bối cảnh**: chưa có service thật nhưng cần chứng minh truy vấn ra đúng số.
- **Cách làm & lý do**: gửi histogram OTLP/HTTP JSON (`aggregationTemporality: 2` = cumulative) mỗi giây trong 30s, count tăng dần: 9 request 200 + 1 request 500 mỗi giây → tỉ lệ lỗi mong đợi đúng 0.1, đo được 0.1. Mọi PromQL của dashboard được trích từ JSON và gửi tới Prometheus để bắt lỗi cú pháp.
- **Bẫy / lưu ý**: `rate()` cần ít nhất 2 mẫu trong cửa sổ → phải gửi nhiều lần và chờ vài lượt scrape (5s), gửi một lần là rate rỗng. Trong OTLP JSON, số nguyên 64-bit (`count`, `timeUnixNano`, `intValue`) viết dạng **chuỗi**.
- **Code**: [grafana-red.test.sh — TC03](../../../../../../scripts/test/grafana-red.test.sh)
