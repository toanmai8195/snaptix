## os.Exit bỏ qua defer → pattern run() error
- **Chủ đề**: `go/defer`, `go/errors`
- **Bối cảnh**: ở P0-T05, `ListenAndServe` lỗi → `os.Exit(1)` → `defer pool.Close()` không bao giờ chạy.
- **Cách làm & lý do**: `defer` chạy khi hàm **return** (hoặc panic lan qua); `os.Exit` kết thúc process ngay, không unwind stack (khác Java: `System.exit` vẫn chạy shutdown hook). Toàn bộ logic chuyển vào `run(cfg, logger) error`; `main` là chỗ **duy nhất** gọi `os.Exit`. Lỗi bọc ngữ cảnh bằng `%w` và trả lên để `main` log **một lần**, không log ở mọi tầng. `defer func() { pool.Close(); logger.Info(...) }()` khi cần làm nhiều việc.
- **Bẫy / lưu ý**: `defer` chạy LIFO — pool đăng ký trước server nên đóng **sau** cùng, đúng thứ tự mong muốn.
- **Code**: [cmd/server/main.go#L22-L70 — main, run](../../../../server/services/core/cmd/server/main.go#L22-L70)

## Signal, goroutine, channel, select
- **Chủ đề**: `go/signal`, `go/goroutine`, `go/channel`
- **Bối cảnh**: `docker stop` / K8s gửi **SIGTERM**, chờ grace period rồi gửi **SIGKILL** (không bắt được, `defer` không chạy); Ctrl-C gửi **SIGINT**. Mặc định Go chết ngay khi nhận hai signal này.
- **Cách làm & lý do**: `signal.Notify(sigCh, SIGINT, SIGTERM)` chuyển signal vào channel thay vì giết process. Server chạy trong goroutine (`go func() { errCh <- srv.Serve(ln) }()`), goroutine chính `select` chờ **hoặc** server lỗi **hoặc** yêu cầu dừng. Channel **buffer 1**: `errCh` — goroutine gửi `ErrServerClosed` xong là thoát dù không ai đọc (không rò goroutine); `sigCh` — tài liệu `signal.Notify` yêu cầu, không thì signal tới lúc chưa ai đọc bị bỏ. Ngay sau signal đầu gọi `signal.Stop` → signal lần 2 về mặc định → giết process ngay (thoát khẩn khi shutdown treo, exit 143 = 128 + 15).
- **Bẫy / lưu ý**: `signal.NotifyContext` ở Go 1.24 chỉ huỷ context, không cho biết signal nào (xem source: bên trong là `Notify` + goroutine) → tự viết `shutdownContext` để log tên signal. Gửi signal cho `go run` không tới thẳng server — test bằng binary đã build.
- **Code**: [cmd/server/main.go#L74-L92 — shutdownContext](../../../../server/services/core/cmd/server/main.go#L74-L92)

## http.Server.Shutdown có timeout, Close khi quá hạn
- **Chủ đề**: `go/net-http`, `go/context`
- **Bối cảnh**: `srv.Close()` cắt ngay mọi kết nối → request đang chạy nhận "empty reply" (curl exit 52), context request bị huỷ (`Ping` trả `context canceled`).
- **Cách làm & lý do**: `srv.Shutdown(ctx)`: (1) đóng listener → kết nối mới bị từ chối (curl exit 7); (2) đóng kết nối keep-alive rảnh; (3) chờ request đang chạy. Trả `nil` khi hết request, `context.DeadlineExceeded` khi hết giờ — và **không** tự cắt request còn lại → gọi thêm `srv.Close()`, log `WARN`, trả lỗi (exit 1 để người vận hành biết có request bị cắt). Context của Shutdown tạo mới từ `context.Background()` + `WithTimeout(cfg.ShutdownTimeout)`: ctx signal đã bị huỷ, dùng lại thì Shutdown trả về ngay. `CORE_SHUTDOWN_TIMEOUT` parse bằng `time.ParseDuration` (`"15s"`, `"500ms"`), tự kiểm tra `> 0` vì ParseDuration nhận số âm và `"0s"`.
- **Bẫy / lưu ý**: timeout phải **nhỏ hơn** grace period của nền tảng: K8s mặc định 30s, `docker stop` mặc định **10s** < 15s mặc định của core → khi chạy image (P0-T07) cần `docker stop -t 20` hoặc `stop_grace_period`. Chưa đủ cho rolling deploy: cần readiness 503 + `preStop` để load balancer rút pod trước khi listener đóng (tiêu chí hoàn thành G3, làm sau).
- **Code**: [cmd/server/main.go#L97-L125 — serve](../../../../server/services/core/cmd/server/main.go#L97-L125), [cmd/server/config.go#L21-L44 — loadConfig](../../../../server/services/core/cmd/server/config.go#L21-L44)
- **Tham khảo**: [net/http — Server.Shutdown](https://pkg.go.dev/net/http#Server.Shutdown), [Kubernetes — Pod termination](https://kubernetes.io/docs/concepts/workloads/pods/pod-lifecycle/#pod-termination)

## Thiết kế để test được: net.Listen, cổng :0, ctx thay cho signal
- **Chủ đề**: `go/testing`, `go/context`, `go/net`
- **Bối cảnh**: muốn test "request chậm + SIGTERM" (TC03–TC05) bằng unit test, không gửi signal thật vào process test, không đụng cổng 8080.
- **Cách làm & lý do**: tách `serve(ctx, srv, ln, timeout, logger)`: nhận **context** làm tín hiệu dừng (test gọi `cancel()`) và **listener** do nơi gọi mở. `run` gọi `net.Listen` trong goroutine chính → cổng bị chiếm trả lỗi ngay, log `listening` chỉ khi đã nghe thật (`ln.Addr()` = địa chỉ OS cấp, vd `[::]:8080`). Test mở `127.0.0.1:0` — OS chọn cổng trống, test song song không giành cổng. Handler chậm giả báo `started` qua channel (`close(started)`) để cancel đúng lúc request đang chạy, không đoán bằng `sleep`.
- **Bẫy / lưu ý**: Shutdown chạy bất đồng bộ sau `cancel()` → test "kết nối mới bị từ chối" phải thử lại trong vòng lặp có deadline. `CancelFunc` gọi nhiều lần vô hại. Chạy `-count=5 -race` để bắt test chập chờn.
