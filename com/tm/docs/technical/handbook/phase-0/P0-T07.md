- **Chủ đề**: `go/interface`
- **Bối cảnh**: `/readyz` cần kiểm tra DB; thói quen Java sẽ tạo `IDatabase` cạnh implementation.
- **Cách làm & lý do**: `httpx` tự khai báo interface một method `Pinger{ Ping(ctx) error }` — đúng thứ nó cần. `*pgxpool.Pool` thoả interface này mà không cần biết `httpx` tồn tại (Go thoả interface ngầm). Test dùng `pingerFunc` (hàm thoả interface) thay vì mock framework.

## Wiring tay trong `main.go`, `run()` trả error
- **Chủ đề**: `go/structure`
- **Bối cảnh**: thay cho Dagger/Guice.
- **Cách làm & lý do**: `main` chỉ gọi `run(ctx)` và `os.Exit(1)` khi lỗi; `run` đọc config → logger → pool → router → server, đọc từ trên xuống là thấy toàn bộ đồ thị dependency. `run` trả `error` nên `defer pool.Close()` vẫn chạy (gọi `os.Exit` trong hàm có `defer` sẽ bỏ qua defer).
- **Code**: [main.go#L25-L44 — run](../../../../server/services/core/cmd/server/main.go#L25-L44)

## `/healthz` vs `/readyz`, timeout bằng context
- **Chủ đề**: `go/context`, `observability`
- **Bối cảnh**: orchestrator cần phân biệt "process sống" với "sẵn sàng nhận traffic".
- **Cách làm & lý do**: `/healthz` không đụng phụ thuộc (luôn 200 khi process chạy); `/readyz` `Ping` DB với `context.WithTimeout(req.Context(), 2s)` → DB treo vẫn trả 503 nhanh, và nếu client ngắt kết nối thì ping cũng dừng theo `req.Context()`. `readyTimeout` là biến package để test ghi đè (50ms) thay vì chờ 2s.
- **Bẫy / lưu ý**: pgxpool mở kết nối **lười** — `NewWithConfig` không lỗi khi DB chưa chạy; service vẫn khởi động, `/readyz` báo thật. Đặt `ConnectTimeout` mặc định 2s, nếu không `Ping` có thể treo tới timeout của OS.
- **Code**: [router.go#L22-L38 — readyz](../../../../server/services/core/internal/httpx/router.go#L22-L38), [pool.go#L19-L22 — ConnectTimeout](../../../../server/pkg/postgres/pool.go#L19-L22)
