## Migration là gì, khác initial script ở đâu
- **Chủ đề**: `pg/migration`
- **Bối cảnh**: code Go chỉ chạy được khi DB đã có đúng bảng/cột; schema thay đổi dần theo phase trên DB đang có dữ liệu.
- **Cách làm & lý do**: mỗi thay đổi schema là một file SQL đánh số (`00001_init.sql`), có phần `-- +goose Up` / `-- +goose Down`, nằm trong git cùng code. Khác initial script (chạy một lần lúc DB trống): migration chạy **tăng dần**, chỉ chạy phần mới, nhớ đã chạy tới đâu, hoàn tác được. Không dùng `/docker-entrypoint-initdb.d/` vì chỉ chạy khi volume trống và không có ở production/testcontainers.
- **Bẫy / lưu ý**: migration là bước riêng, **không** để core tự chạy khi khởi động (nhiều instance tranh nhau; migration nặng cần chọn thời điểm).
- **Code**: [00001_init.sql](../../../../server/db/core/migrations/00001_init.sql)

## Cơ chế goose: bảng version + transaction của PG
- **Chủ đề**: `pg/migration`, `pg/transaction`
- **Bối cảnh**: vì sao chạy `up` nhiều lần vẫn an toàn, và lỗi giữa chừng không để DB dở dang.
- **Cách làm & lý do**: goose đọc thư mục → version từ tên file; đọc bảng `goose_db_version` (goose tự tạo, là bảng thường) → tính file pending; mỗi file chạy trong `BEGIN … SQL … INSERT version … COMMIT`. `down` chạy phần Down rồi xoá dòng version. Sự an toàn đến từ **PostgreSQL**: PG cho DDL (`CREATE/ALTER TABLE`) nằm trong transaction nên rollback được — MySQL/Oracle thì không.
- **Bẫy / lưu ý**: goose chỉ nhớ **số version**, không kiểm nội dung → migration đã merge thì **không sửa**, muốn đổi thì viết file mới. `CREATE INDEX CONCURRENTLY` không chạy trong transaction → cần `-- +goose NO TRANSACTION`. Hàm PL/pgSQL có `;` bên trong → bọc `-- +goose StatementBegin/End`.

## Pin công cụ Go bằng `go run pkg@version`
- **Chủ đề**: `go/tooling`
- **Bối cảnh**: cần goose cùng phiên bản trên mọi máy mà không cài global, không đụng `go.mod`.
- **Cách làm & lý do**: `go run github.com/pressly/goose/v3/cmd/goose@v3.26.0` — Go tải đúng bản vào module cache rồi chạy (giống `npx pkg@version`). Build tag `-tags "no_mysql no_sqlite3 …"` loại driver DB không dùng: lần đầu ~30s → ~4s.
- **Bẫy / lưu ý**: goose v3.28 đòi Go 1.26 (`go list -m -json mod@ver` → `GoVersion`). Mặc định `GOTOOLCHAIN=auto` sẽ âm thầm tải toolchain mới; đặt `GOTOOLCHAIN=local` để lỗi rõ ràng.
- **Code**: [scripts/migrate.sh#L16-L27 — GOOSE_VERSION, goose()](../../../../../../scripts/migrate.sh#L16-L27)

## Bash script an toàn
- **Chủ đề**: `bash`
- **Bối cảnh**: gói lệnh goose dài thành `scripts/migrate.sh`.
- **Cách làm & lý do**: `set -euo pipefail` (dừng khi lỗi, cấm biến chưa đặt, pipe lỗi là lỗi); `ROOT` tính từ vị trí script (`BASH_SOURCE`) để gọi từ đâu cũng đúng; `${CORE_DATABASE_URL:-mặc định}` cho phép CI/testcontainers ghi đè; `"$@"` chuyển nguyên tham số. `create` thêm `-s` → đánh số tuần tự (`00002_…`) để hai nhánh cùng tạo migration sẽ xung đột rõ khi merge, thay vì timestamp lọt qua và chạy sai thứ tự.
- **Code**: [scripts/migrate.sh#L14-L45](../../../../../../scripts/migrate.sh#L14-L45)
