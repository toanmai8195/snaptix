## Pin công cụ Go bằng `go run pkg@version` (không cài global, không làm phình go.mod)
- **Chủ đề**: `go/tooling`
- **Bối cảnh**: cần goose cùng phiên bản trên máy dev và CI, nhưng `cmd/goose` import driver của mọi DB — thêm vào `go.mod` (kể cả `tool` directive của Go 1.24) sẽ kéo hàng chục dependency vào `go.sum` và `go_deps` của Bazel.
- **Cách làm & lý do**: `go run -tags "no_mysql no_sqlite3 ..." github.com/pressly/goose/v3/cmd/goose@v3.26.0` — tải và build đúng phiên bản vào module cache, không đụng `go.mod` của dự án. Build tag `no_*` của goose loại driver không dùng → lần đầu build ~9s, sau đó dùng cache.
- **Code**: [scripts/migrate.sh#L13-L22 — GOOSE_VERSION, tags, goose()](../../../../../../scripts/migrate.sh#L13-L22)

## Bẫy: dependency yêu cầu Go mới hơn → tự tải toolchain
- **Chủ đề**: `go/tooling`
- **Bối cảnh**: goose v3.28.0 khai báo `go 1.26`; với `GOTOOLCHAIN=auto` (mặc định) Go âm thầm tải go1.26.8 để chạy — build "vẫn pass" nhưng dự án ngầm phụ thuộc toolchain khác.
- **Cách làm & lý do**: kiểm tra `go list -m -json <mod>@<ver>` → trường `GoVersion`; chọn v3.26.0 (`go 1.23`) và ép `GOTOOLCHAIN=local` để lỗi rõ ràng thay vì tự tải. Test TC01 kiểm tra output không có "switching to go".
- **Code**: [scripts/migrate.sh#L22 — GOTOOLCHAIN=local](../../../../../../scripts/migrate.sh#L22)

## goose: `version` là version của DB, không phải của công cụ
- **Chủ đề**: `pg/migration`
- **Bối cảnh**: `goose ... version` cần kết nối DB và in version schema đang áp dụng.
- **Cách làm & lý do**: phiên bản công cụ dùng cờ `goose -version` → bọc thành `migrate.sh --tool-version`. Version schema đọc từ bảng `goose_db_version` (mỗi DB một bảng riêng → core và analytics độc lập).
- **Code**: [scripts/migrate.sh#L24 — --tool-version](../../../../../../scripts/migrate.sh#L24)

## Quy ước migration: đánh số tuần tự, luôn có Down
- **Chủ đề**: `pg/migration`
- **Bối cảnh**: nhiều người/nhiều nhánh tạo migration; timestamp dễ lệch thứ tự khi merge, số tuần tự dễ phát hiện trùng.
- **Cách làm & lý do**: `goose create ... -s` → `00002_ten.sql`. `scripts/check-migrations.sh` bắt: tên sai `NNNNN_ten.sql`, trùng số, thiếu `-- +goose Up/Down`. Migration đầu chỉ là mốc version 1 (`SELECT ...`), schema thật bắt đầu từ Phase 1.
- **Code**: [scripts/migrate.sh#L34-L36 — create tuần tự](../../../../../../scripts/migrate.sh#L34-L36), [scripts/check-migrations.sh](../../../../../../scripts/check-migrations.sh)
