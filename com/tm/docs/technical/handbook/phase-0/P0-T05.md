## Package main và thư mục cmd/
- **Chủ đề**: `go/basics`, `bazel`
- **Bối cảnh**: core cần một binary HTTP server; sau này thêm binary worker.
- **Cách làm & lý do**: chỉ package tên `main` có hàm `main()` mới build ra file chạy được; mọi package khác là thư viện. Mỗi binary một thư mục `services/core/cmd/<tên>/` → `cmd/server`, sau này `cmd/worker`, dùng chung code trong `internal/`. Gazelle sinh `go_library` `server_lib` (private) + `go_binary` `server` (`embed = [":server_lib"]`) để `go_test` cũng embed được cùng library.
- **Bẫy / lưu ý**: `go run` build vào thư mục tạm rồi chạy **process con**; kill process `go run` (vd `pkill -f "go run ..."`) có thể để lại process con mồ côi (PPID 1) vẫn giữ cổng — gặp thật khi chạy test case, các request sau đó đi vào process cũ. Khi test tự động, `go build -o` rồi chạy binary; kiểm tra cổng bằng `lsof -nP -iTCP:8080 -sTCP:LISTEN`.
- **Code**: [cmd/server/main.go#L16-L47 — main](../../../../server/services/core/cmd/server/main.go#L16-L47)

## net/http: Handler, HandlerFunc, http.Server có timeout
- **Chủ đề**: `go/net-http`
- **Bối cảnh**: cần HTTP server; thư viện chuẩn đã đủ.
- **Cách làm & lý do**: `http.Handler` là interface một method `ServeHTTP(ResponseWriter, *Request)`; `http.HandlerFunc` là kiểu hàm có sẵn `ServeHTTP` → hàm thường thành `Handler` không cần struct. Server tự tạo goroutine cho mỗi kết nối (không cấu hình thread pool) → handler phải an toàn khi chạy song song. Tạo `&http.Server{...}` thay vì `http.ListenAndServe(addr, h)` để giữ biến `srv` (P0-T06 gọi `Shutdown`) và đặt `ReadHeaderTimeout` — mặc định server **không có timeout nào**, client gửi header nhỏ giọt giữ kết nối mãi (slowloris).
- **Bẫy / lưu ý**: không gọi `WriteHeader` → status 200; `Content-Type` được đoán từ body.
- **Code**: [cmd/server/main.go#L36-L40 — http.Server](../../../../server/services/core/cmd/server/main.go#L36-L40)

## ResponseWriter là interface, *Request là con trỏ tới struct
- **Chủ đề**: `go/interface`, `go/pointer`
- **Bối cảnh**: câu hỏi "vì sao `w http.ResponseWriter` không có `*` còn `r *http.Request` có".
- **Cách làm & lý do**: giá trị interface bên trong đã gồm (kiểu cụ thể, con trỏ tới dữ liệu) — server truyền `*http.response` → gọi `w.Write` ghi thẳng vào object của server. Con trỏ tới interface (`*ResponseWriter`) gần như không bao giờ dùng. `Request` là struct lớn (~20 field) và cần dùng chung giữa router, middleware, handler → truyền `*Request` để không copy. Quy tắc: interface không cần con trỏ; struct lớn / cần chia sẻ / cần sửa → con trỏ; struct nhỏ bất biến (`time.Time`) → giá trị.
- **Bẫy / lưu ý**: dù là con trỏ, không sửa request được truyền vào; muốn gắn context mới dùng `r.WithContext(ctx)` (trả bản copy nông). Là interface nên middleware bọc được `w` (xem mục log) và test dùng `httptest.ResponseRecorder`.

## chi router và internal/
- **Chủ đề**: `go/chi`, `go/package`
- **Bối cảnh**: `ServeMux` chuẩn nhận mọi method trên một path; cần route theo method, 405, và sau này tham số path, nhóm route, middleware.
- **Cách làm & lý do**: chi (`chi.NewRouter()`, `r.Get`, `r.Use`) vẫn là `http.Handler`, handler vẫn chữ ký chuẩn, middleware là `func(http.Handler) http.Handler` → code không bị khoá vào framework. gin/echo bị loại vì handler dùng kiểu riêng (`*gin.Context`). Router + health đặt trong `services/core/internal/httpx`: compiler **cấm** code ngoài `services/core/...` import `internal/`; Gazelle phản ánh bằng `visibility = ["//services/core:__subpackages__"]`. Chữ hoa = export (`NewRouter`), chữ thường = trong package (`healthz`).
- **Bẫy / lưu ý**: bỏ lỗi phải **tường minh** `_, _ = io.WriteString(w, "ok")` — errcheck (golangci-lint, P0-T10) báo nếu lờ đi. `_` cho tham số không dùng.
- **Code**: [httpx/router.go#L12-L18 — NewRouter](../../../../server/services/core/internal/httpx/router.go#L12-L18)

## Config từ env, truyền getenv như tham số
- **Chủ đề**: `go/config`, `go/errors`, `go/testing`
- **Bối cảnh**: 3 biến `CORE_HTTP_ADDR`, `CORE_DATABASE_URL`, `LOG_LEVEL` theo [local-setup](../../local-setup.md), có mặc định cho local.
- **Cách làm & lý do**: `loadConfig(getenv func(string) string) (config, error)` — chạy thật truyền `os.Getenv`, test truyền closure đọc `map` → không `os.Setenv`, test song song không giẫm nhau (nhẹ hơn tạo interface `EnvProvider` + mock). Kiểu `config` không export, nằm trong package `main` vì chỉ `main` dùng (quy tắc 3 tầng: copy, không tạo `pkg/config`). Không dùng viper/envconfig — 3 biến chưa đáng một dependency. Lỗi là giá trị: `fmt.Errorf("LOG_LEVEL %q: %w", level, err)` — `%q` in có nháy (thấy khoảng trắng thừa), `%w` bọc lỗi gốc để `errors.Is/As`.
- **Bẫy / lưu ý**: `os.Getenv` không phân biệt "không đặt" với "đặt rỗng" (dùng `os.LookupEnv` nếu rỗng có nghĩa riêng). Struct toàn field so sánh được → so cả struct bằng `got != tt.want` trong test.
- **Code**: [cmd/server/config.go#L17-L29 — loadConfig](../../../../server/services/core/cmd/server/config.go#L17-L29), [cmd/server/config_test.go — TestLoadConfig](../../../../server/services/core/cmd/server/config_test.go)

## slog JSON và middleware log request
- **Chủ đề**: `go/slog`, `go/middleware`, `go/closure`
- **Bối cảnh**: P0-NFR1 — log JSON một dòng; cần một dòng log cho mỗi request.
- **Cách làm & lý do**: `slog.New(slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{Level: level}))` — tự thêm `time`, `level`, `msg`; gọi dạng key-value `logger.Info(msg, "k", v, ...)`. `LOG_LEVEL` parse bằng `slog.Level.UnmarshalText` (debug/info/warn/error, không phân biệt hoa thường). Logger truyền **tường minh** (`NewRouter(logger, ...)`) thay vì `slog.Default()` global → thấy phụ thuộc trong chữ ký, test truyền logger ghi vào `bytes.Buffer`. Middleware `logRequests(logger) func(http.Handler) http.Handler` là closure; bọc `w` bằng `middleware.NewWrapResponseWriter` vì `ResponseWriter` không có hàm đọc status.
- **Bẫy / lưu ý**: handler không ghi gì → wrapper `Status()` = 0 nhưng net/http trả 200 → quy đổi. `time.Duration` trong JSON là **nanosecond** (số nguyên). Lỗi config xảy ra trước khi biết level → tạo logger tạm mức info để vẫn ra JSON. Không log `DatabaseURL` (chứa mật khẩu).
- **Code**: [httpx/log.go#L12-L33 — logRequests](../../../../server/services/core/internal/httpx/log.go#L12-L33), [cmd/server/main.go#L50-L52 — newLogger](../../../../server/services/core/cmd/server/main.go#L50-L52)

## pgxpool lười, /readyz với context timeout, interface phía dùng
- **Chủ đề**: `pg/pgx`, `go/context`, `go/interface`, `k8s/probe`
- **Bối cảnh**: P0-FR3 — `/readyz` phản ánh trạng thái PG, không treo khi PG không phản hồi; core phải khởi động được khi PG chưa lên.
- **Cách làm & lý do**: pgx v5 (giao thức PG trực tiếp, kiểu dữ liệu đầy đủ, `COPY`, batch; `lib/pq` chỉ còn bảo trì) + `pgxpool`. `pgxpool.New` chỉ parse URL và tạo pool, **không kết nối** → core chạy khi PG down (không crash-loop trong K8s), URL sai cú pháp vẫn lỗi ngay lúc khởi động. `/readyz`: `context.WithTimeout(r.Context(), 2*time.Second)` + `defer cancel()` → `Ping(ctx)` → 200 / 503. Handler nhận interface `pinger` (1 method) khai báo **trong `httpx`**; `*pgxpool.Pool` thoả tự động (structural typing, không `implements`); test dùng `fakeDB`. Handler factory `readyz(db, logger) http.HandlerFunc` giữ dependency bằng closure thay cho struct controller. `/healthz` (liveness) không kiểm tra DB — nếu có, DB chết → K8s restart mọi pod vô ích; `/readyz` (readiness) chỉ ngừng gửi traffic.
- **Bẫy / lưu ý**: PG **dừng** → lỗi ngay (`connection refused`); PG **treo** (`docker pause`) → chỉ timeout mới cứu, đo được 503 sau 2.003s. `http.Error` rồi phải `return`. pgx v5.9+ đòi Go 1.25 → pin v5.8.0 cho Go 1.24.1. `os.Exit` bỏ qua `defer pool.Close()` — sắp xếp lại ở P0-T06. `docker compose` trong biến shell `$C` không chạy được trên zsh (zsh không tách từ khi mở rộng biến).
- **Code**: [httpx/health.go#L15-L37 — pinger, readyz](../../../../server/services/core/internal/httpx/health.go#L15-L37), [cmd/server/main.go#L27-L34 — pgxpool.New](../../../../server/services/core/cmd/server/main.go#L27-L34), [httpx/health_test.go#L67-L82 — TestReadyzTimeout](../../../../server/services/core/internal/httpx/health_test.go#L67-L82)
