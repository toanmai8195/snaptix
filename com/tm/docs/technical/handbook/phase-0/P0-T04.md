## Workflow mỏng, logic trong script
- **Chủ đề**: `ci`, `github-actions`
- **Bối cảnh**: GitHub Actions không chạy được ở local; logic viết thẳng trong YAML thì chỉ biết đúng/sai sau khi push.
- **Cách làm & lý do**: workflow chỉ checkout, cài toolchain rồi gọi `scripts/ci/run.sh repo|server|app` và `scripts/ci/affected.sh`. Toàn bộ quyết định (chạy gì, test nào) nằm trong script → test được bằng `scripts/test/ci.test.sh`, dev chạy y hệt CI ở máy mình. Workflow được kiểm bằng `actionlint` (pin phiên bản, chạy qua `go run`).
- **Code**: [.github/workflows/ci.yml](../../../../../../.github/workflows/ci.yml), [scripts/ci/run.sh](../../../../../../scripts/ci/run.sh)

## Commit gốc để so sánh: PR vs push
- **Chủ đề**: `ci`, `git`
- **Bối cảnh**: cần biết "thay đổi so với đâu".
- **Cách làm & lý do**: PR dùng `github.event.pull_request.base.sha`; push dùng `github.event.before`. `before` là toàn số 0 khi tạo nhánh mới → coi như không có base → chạy tất cả. Checkout `fetch-depth: 0` để có đủ lịch sử cho `git diff base...HEAD`. Dùng biến môi trường (`env:`) thay vì nhúng `${{ }}` thẳng vào `run:` để tránh script injection.
- **Code**: [ci.yml#L29-L31 — base](../../../../../../.github/workflows/ci.yml#L29-L31), [run.sh#L15 — valid_base](../../../../../../scripts/ci/run.sh#L15)

## Bazel: chỉ test target bị ảnh hưởng bằng rdeps
- **Chủ đề**: `bazel`, `ci`
- **Bối cảnh**: challenge G14 — không chạy `bazel test //...` cho mọi PR khi repo lớn dần.
- **Cách làm & lý do**: file đổi → label `//pkg:file` theo `BUILD.bazel` gần nhất → `bazel query "kind('.*_test rule', rdeps(//..., set(...)))"`: mọi test phụ thuộc (trực tiếp hay gián tiếp) vào file đó. Đổi `BUILD.bazel` → dùng `//pkg:all`. Đổi cấu hình toàn cục (`MODULE.bazel`, `go.mod`, `.bazelrc`, `tools/**`) hoặc file đã xoá → `//...` cho an toàn.
- **Bẫy / lưu ý**: `bazel test` trả **exit 4** khi không có test target nào — không phải lỗi; phải xử lý riêng, nếu không CI đỏ oan khi repo chưa có test.
- **Code**: [bazel-affected-tests.sh#L19-L43](../../../../../../scripts/ci/bazel-affected-tests.sh#L19-L43), [run.sh#L58 — exit 4](../../../../../../scripts/ci/run.sh#L58)

## Gazelle `-mode=diff` giữ BUILD.bazel luôn cập nhật
- **Chủ đề**: `bazel`, `gazelle`, `ci`
- **Bối cảnh**: dev quên chạy gazelle → BUILD.bazel thiếu file mới, build ở máy có cache vẫn "chạy được".
- **Cách làm & lý do**: CI chạy `bazel run //:gazelle -- -mode=diff`; có diff → exit khác 0 và in patch cần áp dụng. Test kiểm chứng: thêm file Go mà không chạy gazelle → job server fail đúng ở bước này.
- **Code**: [run.sh#L30 — gazelle diff](../../../../../../scripts/ci/run.sh#L30)

## Pin công cụ lint theo phiên bản Go của dự án
- **Chủ đề**: `go/tooling`, `ci`
- **Bối cảnh**: golangci-lint / actionlint bản mới nhất yêu cầu Go mới hơn 1.24.
- **Cách làm & lý do**: kiểm `GoVersion` của từng bản (`go list -m -json mod@ver`) → pin golangci-lint **v2.6.2**, actionlint **v1.7.8** (cùng `go 1.24`), chạy qua `GOTOOLCHAIN=local go run ...@ver`. Lint chỉ chạy khi có package Go (`go list ./...` không rỗng) — golangci-lint báo lỗi khi không có gì để phân tích. Test ngược: file gọi `os.Remove` bỏ qua lỗi → CI fail với `errcheck`.
- **Code**: [run.sh#L37-L42 — golangci-lint](../../../../../../scripts/ci/run.sh#L37-L42)
